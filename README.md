# wappsw

![License: MIT](https://img.shields.io/badge/license-MIT-blue)
![Topics](https://img.shields.io/badge/dynamic/json?url=https%3A%2F%2Fapi.github.com%2Frepos%2Fpanzoux%2Fwappsw&label=topics&query=%24.topics&color=blue)

Windows 10 / Windows 11 向けの軽量タスクスイッチャーです。RustとWin32/GDIのみで構築したシンプルな構造で、GUIフレームワークやトレイアイコン、コンソールウィンドウは使用していません。

Migemo機能と辞書データ（BSDライセンス）をアプリ本体に内蔵しているため、外部ファイルを用意することなく単体で快適なローマ字検索が可能です。

[ytakanashi/Tascher](https://github.com/ytakanashi/Tascher) に大きな影響を受けて開発しました。Windows 11でWindows Terminal (`wt.exe`) などのウィンドウ名が「ShellHost」とならないようにするなど、OSの仕様変化に合わせたタスク名表示にしています。

## 動作環境

Windows 10 / Windows 11 で動作します（32bit・64bit のどちらでもビルドできます）。

## 主な機能

* **クイック起動**: ホットキー（デフォルトは Caps Lock）を押すと、開いているウィンドウ一覧をポップアップ表示します。
* **Migemoと辞書内蔵・ローマ字曖昧検索**: キーボードから英字を入力するだけで、Migemo（[rustmigemo](https://github.com/oguna/rustmigemo)）による日本語タイトルの曖昧検索が可能です（日本語を入力しなくても、通常の部分一致として動作します）。
* **キーボード操作**: `↑` / `↓` で選択、`Enter` で切り替え、`Esc` でキャンセルできます。
* **素早い2ウィンドウ切り替え**: 直前までフォーカスしていた順（MRU順）に並ぶため、ホットキーを2回連打するだけで直近の2つのウィンドウを交互に行き来できます。
* **Windows 10 / 11 での名称・アイコン解決**: UWPアプリは `ApplicationFrameHost.exe` の子プロセスである `CoreWindow` から実プロセスを追跡して取得し、その他のアプリ（Windows Terminal等）も分かりやすい名称を取得して表示します。

## 使い方

### 起動と終了

**起動方法**

ダウンロードまたはビルドした `wappsw.exe` を実行します。バックグラウンドで常駐し、ホットキーの入力を待機します（画面上にウィンドウやトレイアイコンは表示されません）。

**終了方法**

ホットキーでウィンドウ一覧を開き、`Ctrl` + `Q` を押すと即座に終了します（確認ダイアログは出ません）。

※この操作にはホットキーが正しく動作していることが前提になります。ホットキーの設定を誤ってどうしても一覧を開けない場合は、タスクマネージャーから `wappsw.exe` を終了してください。

### 基本操作

1. ホットキー（デフォルト: Caps Lock）を押すと、画面中央にウィンドウ一覧が開きます。
2. キーボードで文字を入力し、タイトルやアプリ名で候補を絞り込みます。
* 検索結果が0件になってもリストはクリアされず、直前の絞り込み状態を維持します。


3. `↑` / `↓` で選択し、`Enter` で決定してウィンドウを切り替えます（ポップアップは閉じます）。
4. `Esc` を押すと何もせずに閉ちます。`Ctrl` + `Q` でアプリ自体を終了します。
5. ポップアップが開いた状態でもう一度ホットキーを押すと `Enter` と同じ動きになります。ホットキーを連打することで、直近の2つのウィンドウをすばやく往復できます。
6. 候補が1件に絞り込まれたあと、そのまま 0.5 秒（`autoswitch` で変更可）経過すると自動でそのウィンドウに切り替わります。

## 設定

設定ファイルは `%APPDATA%\wappsw\config.ini` に自動生成されます（初回起動時に未作成の場合）。
※設定の変更を反映するにはアプリの再起動が必要です。

```ini
hotkey=CapsLock
; autoswitch=500
; regexcache=100
; prewarm=true

```

### `hotkey`

ホットキーとして割り当てるキーを指定します。
次の3つに対応しています。（殆どのキーに対応していません）
設定値について、大文字・小文字、`-` / `_` / 半角スペースは無視されます。

| 設定値 | キー |
| --- | --- |
| `CapsLock` / `Caps` | Caps Lock（デフォルト） |
| `ScrollLock` / `Scroll` | Scroll Lock |
| `Insert` / `Ins` | Insert |

※無効な値が設定された場合はログに警告を出力し、デフォルトの `CapsLock` が使われます。

### `autoswitch`（自動切替機能）

検索結果がちょうど1件に絞り込まれた際、`Enter` キーを押さなくても指定時間（ミリ秒）経過後に自動でウィンドウを切り替える機能です（デフォルト: `500`、つまり 0.5 秒待機後に自動切替）。

* コメントアウトや定義がない場合は、デフォルトの 500 ミリ秒で有効になります。
* `autoswitch=250` のように数値で待機時間を変更できます。
* `autoswitch=off`（`no` / `false` / `0` も可）で無効にします。`on` / `yes` / `true` はデフォルトの 500 ミリ秒で有効にします。
* `autoselect` という名前でも同じ設定として扱われます。

### `regexcache`（検索キャッシュ）

入力した検索文字列ごとに、Migemo で変換した正規表現を最近使ったものから指定件数まで保持します（デフォルト: `100`）。同じ文字列をもう一度入力したときや、バックスペースで戻ったときに、変換をやり直さずすぐに絞り込めます。

* `regexcache=0` でキャッシュを無効にします。
* 1件あたり平均約 120 KB、1文字の検索では最大約 800 KB のメモリを使います。数千件のような大きな値はメモリを大量に消費するため推奨しません。

### `prewarm`（1文字検索の事前変換）

起動時にバックグラウンドで `a`〜`z` の1文字検索を事前に変換しておきます（デフォルト: `true`）。Migemo では1文字の検索がもっとも変換に時間がかかる（1文字あたり数十ミリ秒〜0.2 秒程度）ため、検索の1文字目で待たされることがなくなります。

* 起動直後の 1 秒前後、優先度を下げたバックグラウンド処理が走り、数 MB〜十数 MB のメモリを使います。
* `prewarm=false` で無効にします（`true` / `false` のほか `on` / `off`、`yes` / `no`、`1` / `0` も使えます）。
* `regexcache=0` にしていても、事前変換した `a`〜`z` は保持されます。

### 多重起動の防止

二重起動を検知すると「wappsw is already running.」というエラーを表示して自動終了します。

### ログ出力（`-log` オプション。デバッグ用）

通常はログを出力しません。起動時に `-log`（または `--log`）オプションを付けることで `%APPDATA%\wappsw\log.txt` にログを追記出力できます。

```text
wappsw.exe -log

```

## ビルド方法

```text
cargo build --release

```

ビルドすると `target\release\wappsw.exe` に単体で動作する実行ファイルが生成されます。
※Migemo辞書データ（`assets/migemo-compact-dict.bin`）は `include_bytes!` でバイナリ内に直接埋め込まれるため、実行時に外部の辞書ファイルを用意する必要はありません。

## 管理者権限での自動起動について（任意）

Windowsの仕様（UIPI）により、非管理者権限で動いているフック処理は、管理者権限で開いているウィンドウ（管理者権限のターミナル等）にフォーカスがある間、キー入力を受け取ることができません。

常に快適に使用したい場合は、管理者権限のPowerShellで以下のスクリプトを1度実行してください。タスクスケジューラに登録され、OS起動時にUACプロンプトなしで管理者権限で自動起動するようになります。

```powershell
powershell -ExecutionPolicy Bypass -File setup\install-task.ps1

```

※タスクを削除したい場合:

```powershell
Unregister-ScheduledTask -TaskName wappsw -Confirm:$false

```

## 制限事項・既知の挙動

* **修飾キーとの組み合わせ非対応**: v1では `Ctrl+Shift+Space` のような複合ショートカットには対応していません（単体キーのみサポート）。
* **Shiftキーの扱い**: ホットキーが `CapsLock` の場合、Ctrl / Alt / Win キーが同時に押されているときはタスク切り替え画面は表示されません。なお、JIS配列キーボードなどの環境では Caps Lock 単体押しでもOS内部で Shift が押されたと判定されるケースがあるため、タスク切り替えが表示されます (Macキーボード+Parallels Clientで発生)。
* **スキャンコードでの判定**: JIS配列で Caps Lock を押した際に `VK_CAPITAL` ではなく英数キーとして解釈される問題を防ぐため、仮想キー（VK）ではなくハードウェアのスキャンコードで判定しています（Caps Lock: `0x3A` / Scroll Lock: `0x46` / Insert: `0x52`）。スキャンコードの入れ替えがある場合は別キーとなる場合があります。
* **仮想デスクトップ**: 別の仮想デスクトップにあるウィンドウ（非表示化されているもの）は一覧に表示されません。なお、最小化されているウィンドウは表示され、選択すると元に戻ります。
* **UWPアプリの判定**: `ApplicationFrameHost.exe` 経由のウィンドウのみ実体プロセスを解決します。
* **表示位置**: ホットキーを押した時点でアクティブだったウィンドウがあるモニターの中央に表示されます。
* **割り切り**: トレイアイコン、設定画面、終了機能、表示位置指定、多言語対応などは機能を単純に保つため実装していません。
